<h1> Text Analyzer Microservices</h1>

Проект реализует два простых микросервиса на Go:
- **Сервис A (Text Receiver)**: принимает HTTP‑запросы с текстом, генерирует уникальный ID, отправляет текст в сервис B для анализа и хранит статус обработки в памяти.
- **Сервис B (Text Analyzer)**: принимает текст от сервиса A, считает статистику (количество слов, символов, предложений, среднюю длину слова) и синхронно возвращает результат.

Сервисы общаются по HTTP, поддерживают health‑checks, логирование, таймауты при сетевом запросе и корректное завершение (graceful shutdown). Хранение данных реализовано in‑memory в сервисе A.

## 🚀 Быстрый старт

Эта инструкция проведет тебя через все этапы: от клонирования репозитория до проверки работы API.

### 1️⃣ Требования
Перед началом убедись, что у тебя установлены:
- **Git**
- **Go 1.25+**
- **Docker & Docker Compose** 
- **Make**

### 2️⃣ Клонирование репозитория
Открой терминал и выполни:

```bash
git clone https://github.com/tambrama/text_analyzer.git
```
### 2️⃣ Установка зависимостей
Загрузи необходимые Go-модули и инструменты для разработки:

```
# Установка зависимостей проекта
go mod tidy

# Установка утилиты для генерации Swagger-документации
go install github.com/swaggo/swag/cmd/swag@latest

# Установка библиотеки для тестов (если не подтянулась автоматически)
go get github.com/stretchr/testify
```
### 4️⃣ Запуск проекта
Выбери один из способов ниже.

**🐳 Способ А: Через Docker Compose (Рекомендуемый)**
Автоматически поднимает оба сервиса в изолированных контейнерах.
    Сборка и запуск:
```
docker compose up --build
```
1. Доступ к сервисам:
  
Receiver: **http://localhost:8081**

Analyzer: **http://localhost:8082**

Swagger UI: **http://localhost:8081/swagger/index.html**

1. Остановка:
Нажми **Ctrl+C** или выполни в новом окне: ```docker compose down```.

**💻 Способ Б: Локальный запуск (без Docker)**
Требуется запустить два сервиса в разных терминалах.

Терминал 1: Запуск Сервиса B (Analyzer)
```
cd text_analyzer
go run ./cmd/analyzer
# Слушает порт :8082 по умолчанию
```
Терминал 2: Запуск Сервиса A (Receiver)
Необходимо указать адрес анализатора через переменную окружения.
Для CMD (Windows):
```
set ANALYZER_URL=http://localhost:8082
go run ./cmd/receiver
```
Для Linux/Mac:
```
export ANALYZER_URL=http://localhost:8082
go run ./cmd/receiver
```
**Слушает порт :8081 по умолчанию.**

## 🛠 Использование Makefile

В проекте настроен `Makefile` для автоматизации рутинных задач.

| Команда | Описание |
|:---|:---|
| `make` или `make all` | **По умолчанию:** собирает и запускает сервисы в Docker (`docker-up`) |
| `make build` | Собирает бинарные файлы сервисов в папку `build/` |
| `make run` | Собирает и запускает оба сервиса локально (в фоне) |
| `make clean` | Удаляет папку сборки `build/` |
| `make fmt` | Форматирует код во всем проекте (`go fmt`) |
| `make mod` | Обновляет зависимости (`go mod tidy`) |
| `make docker-up` | Собирает образы и запускает контейнеры в фоновом режиме (`-d`) |
| `make docker-down` | Останавливает и удаляет контейнеры |
| `make docker-rebuild` | Полная пересборка: удаляет контейнеры и тома (`-v`), затем запускает заново |
| `make docker-logs` | Показывает логи запущенных контейнеров в реальном времени (`-f`) |
| `make docs` | Генерирует Swagger-документацию для обоих сервисов |

**Пример использования:**
Чтобы сразу собрать и запустить проект в Docker:
```
make docker-up
```

## 🏗 Архитектура

### Технологии
- **Язык**: Go 1.25+
- **Фреймворк**: Uber FX (Dependency Injection, Lifecycle hooks)
- **Хранение**: In-Memory (map + mutex)
- **Контейнеризация**: Docker, Docker Compose
- **Документация**: Swagger (Swag)
- **Тестирование**: `testing`, `testify`, интеграционные тесты
  
### Сервис A: Text Receiver (`:8081`)
Принимает текст, создает задачу со статусом `PENDING`, асинхронно отправляет её в Сервис B и обновляет статус на `DONE`/`FAILED`.
- `POST /api/v1/text` — создать задачу.
- `GET /api/v1/status/{id}` — получить статус и результат.
- `GET /api/v1/health` — проверка здоровья.
- `GET /swagger/index.html` — Swagger UI.

### Сервис B: Text Analyzer (`:8082`)
Синхронно анализирует текст и возвращает статистику.
- `POST /api/v1/analyze` — анализ текста.
- `GET /api/v1/health` — проверка здоровья.
- `GET /swagger/index.html` — Swagger UI.

**Взаимодействие**:
- Сервис A вызывает `POST analyzer/api/v1/analyze` с JSON `{id, text}`.
- Сервис B возвращает JSON со статистикой.
- Сервис A сохраняет результат и делает его доступным по `GET /api/v1/status/{id}`.
